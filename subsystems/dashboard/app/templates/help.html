1 Signing in

  • First ever visit: if no account exists, you're sent to a one-time setup page to create the first administrator. It locks permanently afterward.
  • Normal sign-in: email + password. If you've registered a passkey, you'll be prompted for it (or it may replace the password).
  • The left sidebar is the navigation. What you see depends on your role — a read-only account sees the fleet but no admin tools.

2 Server Status (home)

  • Server Health — live tiles: containers (hbbs/hbbr), CPU, memory, disk, devices online, uptime. Memory/disk show the alert threshold and turn amber/red near it.
  • Server Info — status, host, ports, running server/client versions (with “update available” badges), and the public key clients use.
  • Backups — last backup status; admins get Back up now and Download latest.
  • Admins also see one-click banners to update the RustDesk server or the client version used for new installers.

3 Adding devices (installing the client)

Devices appear automatically once the client is installed and pointed at your server:

  • Open (or create) the device's Client Group.
  • Under Installers, build one for the platform (Windows / macOS / Linux). It's pre-configured with your server, key and the group's settings — nothing to type on the client.
  • Share it via a download link or the built file, and run it on the machine.
  • Within a minute the device appears on Devices and in its group, reporting name, OS, user, CPU, memory and version.

4 Devices

  • Lists every machine with live online / in session / offline status, computer, OS, IP and group, sorted by label (unlabeled last).
  • Recently registered — devices added in the last 7 days that still need a client group, newest first. Assign to Group sets the group without touching the label; the device then leaves the panel.
  • Filter with the search box; ⓘ Details shows full reported details and recent sessions.
  • Connect (video icon) launches your local RustDesk app to that device; Terminal (>_) opens a RustDesk terminal session.
  • Edit sets a label and moves the device between groups. Delete removes it from the dashboard (use for duplicates/decommissioned machines) — if that client ever communicates again, it reappears automatically.
  • Sort & columns — click any column header to sort (numbers, sizes and durations sort by value); use the Columns button to show/hide columns, including the detail columns (User, OS Build, CPU, Cores, Memory, Client Version) that are hidden by default. Choices are remembered per browser.

5 Client Groups

  • Groups organize devices (per customer, internal vs. external). A group is a label plus its own installers and settings — not separate infrastructure.
  • Create a group with a name and optional unattended password (baked into its installers). Open it to manage devices, installers, links and settings.
  • Managed client settings (each Not managed / On / Off): Automatic RustDesk updates, and Remote settings changes (whether a connected tech can change RustDesk's own settings on the device).
  • The groups list and the device list inside a group both support sorting (click a header) and column show/hide via the Columns button, remembered per browser. A group's devices are sorted by label.
  • Edit a device right from the group page (label, client group, delete) — you stay on the group page afterwards.
  • Branding gives the group's installers their own app name and icon. Managers can click the unattended-password badge to copy it.

5b Dynamic groups

  • Saved filters such as “Windows 10 devices” or “not seen in over a year”. Their devices are worked out from the rules each time you open them, so they stay current, and a device can be in any number of them.
  • New Dynamic Group — start from a template or build rules on OS, OS support status, last seen, registered, last remote session, status, client group, label, computer, user, RustDesk version, memory, CPU, cores or IP; match all or any. The preview shows how many devices match as you edit.
  • Open one to see its devices (Connect / Terminal) or Export CSV. Anyone can view; creating and editing needs Manage devices.
  • OS support status follows Microsoft's and Apple's end-of-support dates: End of support, Ending within 6 months, Supported, or Unknown (Linux/not reported). Windows is judged by exact release and edition, Macs by macOS version (Apple gives no advance dates, so a supported Mac has none — it shows End of support once Apple stops security updates). Dates update automatically every day from endoflife.date, so new Windows and macOS releases are covered.

6 Download links

  • Share a link from a group page instead of a binary — with optional expiry and download limit.
  • Email it to the client directly, or revoke it anytime.
  • The public page always serves the group's newest installer and is unlisted.

7 Roles & permissions

  • Access is controlled by roles. Viewing is always allowed; capabilities gate who can change things.
  • Built-in: Administrator (everything, locked), Technician (devices + groups), Viewer (read-only).
  • Admins can create custom roles with a capability checkbox matrix under Admin → Roles & permissions, and assign them on the Users page. The UI hides actions a role can't use; the server enforces them regardless.
  • The Admin menu (including Reports) appears for any role with at least one admin capability, so a Technician doesn't see it.

8 Admin tools

  • Backup & Restore — off-site destination (S3 / Wasabi / Backblaze B2 / Spaces / MinIO), encryption, test, back up, download, restore.
  • Installer signing — Authenticode-sign Windows installers with Azure Trusted Signing (no SmartScreen “unknown publisher” warning); automatic after each build, or Sign / Re-sign per installer on the group page.
  • Email templates (see below), Reports (see below), Roles & permissions, Export device inventory (CSV), Restart relay (brief session drop), Prune logs.

8b Reports

  • Twelve reports under Admin → Reports: Fleet overview, Device inventory, OS support, Inactive devices, RustDesk versions, Hardware, Data quality, Client group health, Remote sessions, New devices, Installers & download links, User activity.
  • Filter any report to one client group (or devices with none); activity reports also take a period. Every table has Download CSV; Print makes a clean printout or PDF.
  • Colors mean something: breakdowns show a colored split bar (a category keeps its color when filtered; small ones fold into gray “Other”); sessions and new devices are column charts; status badges are green ✓ good, amber ! attention, red ✕ problem, gray – unknown; tiles get a red/amber stripe when the number is a problem. Hover a bar for its exact value.
  • Prepare client recommendations with Client group health and OS support, filtered to that client.

9 Users

  • Add a user — email, name, role, group access; auto or manual password, optionally emailed.
  • Change a user's role or group access, reset password, and manage passkeys / MFA (revoke, reset to password, send a setup reminder).

10 Logs

  • Audit trail in category tabs: All, Clients, Remote sessions, Installers, Groups, Users & auth, Notifications, Server, Other — each with a filter.
  • Remote sessions shows each connection to a device: which device, when, and how long. (The client reports the device side, not which technician connected.)

11 Backups

  • Protect the server keypair (every client is tied to it) and the databases. A nightly backup runs automatically; you can also back up on demand.
  • Set an off-site destination and encryption passphrase under Admin → Backup & Restore, then test and enable. Local-only backups don't survive losing the server.
  • Retention is separate for each copy: local archives kept on the server (default 14), and off-site copies kept in the bucket (0 = keep all; pruning needs s3:DeleteObject).
  • Restore takes a safety snapshot first, replaces the keypair + databases, and restarts the relay. Clients reconnect without reconfiguration (same key).
  • Off-site archives are listed too, with Restore (downloads from the bucket, then restores) and Delete. Restore needs s3:GetObject; delete needs s3:DeleteObject.

12 Notifications & alerts

  • SMTP for outbound mail (send a test). Event triggers choose which events email you: device registered / came online / went offline / deleted, installer built / deleted / downloaded, user created / deleted, new server or client version, memory or disk high.
  • Device alerts are checked every 30 seconds. New device registered fires as soon as a device registers — it doesn't wait for a group. Came online / went offline fire on state changes of known devices. A dashboard restart never floods you.
  • Server health alerts — set memory and disk thresholds; you're emailed when usage crosses them (debounced). These are the markers on the Server Health tiles.
  • Delivery log shows recent sends and whether they succeeded.

12b Email templates

  • Admin → Email templates (Manage notifications) controls every email: alerts, the new-user welcome, the passkey reminder and the client download-link email.
  • Design — logo (sent inside the email), brand names for team and client emails, header / button / page colors, font and footers.
  • Each email — edit subject, heading, message, closing text and button text; click a {placeholder} to insert it. A blank line starts a paragraph, **text** is bold, and a paragraph whose placeholders are all empty is skipped. Hide the details table or Reset to default.
  • Live preview while you type; Send test to me emails the saved version with sample data.

13 My account

  • Update your name/email, change your password, and register or remove passkeys (Touch ID, Windows Hello, security key) — choosing whether password sign-in stays enabled.
  • Theme — the switch at the bottom of the sidebar picks Light, Dark or Auto (follows your computer). Saved per browser.
